# 장편한외과 웹블로그 디자인 레퍼런스 및 반영 전략

조사일: 2026-07-10

대상: https://jangclinic.kr/

## 결론

장편한외과에 적합한 방향은 한 사이트를 복제하는 것이 아니라 다음 세 축을 조합하는 것이다.

- 의료 신뢰와 실재감: 차움, 루닛
- 콘텐츠 편집과 탐색: 토스 테크, 채널톡 블로그, 모두싸인 블로그
- 문의·방문 전환: 그리팅, 토스 랜딩

추천 콘셉트는 **전문성이 느껴지는 지역병원의 에디토리얼 홈**이다. 시각적으로는 차분하고 정돈되어야 하지만, 의료기관의 실제 공간·의료진·진료 정보가 스타트업식 그래픽보다 앞에 와야 한다.

권장 구성 비중은 의료 신뢰 45%, 콘텐츠 편집 35%, 전환 구조 20%다.

## 1. 의료·헬스케어 레퍼런스

### 차움 — 실제 공간이 만드는 브랜드 신뢰

출처: https://www.chaum.net/

![차움 홈페이지](./references/01-chaum-home.png)

가져올 점:

- 실제 건물과 공간 사진을 첫 화면의 주인공으로 사용한다.
- 한 문장의 의료 약속과 실제 장소가 함께 보여 실재감이 높다.
- 예약, 결과조회, 증명서, 의료진 검색 같은 핵심 행동을 하나의 고정 서비스 바에 묶는다.
- 로고와 따뜻한 브론즈 계열을 일관되게 사용한다.

가져오지 않을 점:

- 큰 프로모션 팝업과 지나치게 많은 상단 메뉴
- 장편한외과에 맞지 않는 호텔·럭셔리 톤

### 루닛 — 전문성을 큰 문장과 증거로 보여주는 방식

출처: https://www.lunit.io/ko/

![루닛 홈페이지](./references/02-lunit-home.png)

가져올 점:

- “인공지능 기술로 암을 정복합니다”처럼 첫 문장에서 정체성이 끝난다.
- 큰 타이포그래피, 넉넉한 여백, 절제된 그라데이션으로 의료 기술을 현대적으로 보이게 한다.
- 도입 기관, 국가, 논문, 파트너십 같은 수치를 초반에 제시해 신뢰를 만든다.

장편한외과 적용:

- “대장항문 질환, 정확히 설명하고 필요한 치료만 권합니다”처럼 진료 철학을 한 문장으로 만든다.
- 개원 연도, 전문의 경력, 누적 진료·수술 관련 검증 가능한 수치가 있을 때만 증거 블록으로 사용한다.
- 기술 스타트업처럼 추상적으로 보이지 않도록 실제 의료진·공간 사진을 함께 사용한다.

### 서울아산병원 질환백과 — 시각보다 정보 구조 참고

출처: https://www.amc.seoul.kr/asan/healthinfo/disease/diseaseSubmain.do

가져올 점:

- 질환명 검색, 신체 부위별, 질환군별, 많이 찾는 질환으로 진입 경로가 나뉜다.
- 환자가 정확한 병명을 몰라도 증상·부위에서 시작할 수 있다.

장편한외과 적용:

- `증상으로 찾기`: 혈변, 항문 통증, 변비, 복통, 배변 습관 변화
- `진료로 찾기`: 치핵, 치루, 치열, 대장내시경, 탈장, 담낭
- `상황으로 찾기`: 바로 진료가 필요한 경우, 검사 전 준비, 수술 후 관리

대형병원의 복잡한 전체 메뉴와 정보 밀도는 가져오지 않는다.

### 365mc — 포지셔닝만 참고하고 시각 표현은 피하기

출처: https://365mc.co.kr/

![365mc 프로모션 팝업](./references/11-avoid-365mc-popup.png)

가져올 점은 “지방 하나만”처럼 한 분야를 명확하게 소유하는 포지셔닝이다. 반면 대형 팝업, 과장된 캠페인 비주얼, 과도한 전환 압박은 장편한외과의 의료 신뢰와 맞지 않는다.

## 2. 콘텐츠 허브 레퍼런스

### 토스 테크 — 가장 중요한 콘텐츠 구조 레퍼런스

출처: https://toss.tech/

![토스 테크 목록](./references/03-toss-tech-home.png)

가져올 점:

- 첫 화면에 대표 글의 제목, 설명, 이미지가 동시에 보인다.
- 대표 글 아래에 전체 글과 인기 글이 바로 이어져 빈 화면이 없다.
- 카테고리가 Engineering, Design, Product처럼 짧고 명확하다.
- 카드마다 제목과 한 문장의 읽을 이유가 분명하다.

![토스 테크 글 상세](./references/04-toss-tech-article.png)

글 상세에서 특히 가져올 점:

- 커버 이미지보다 제목과 작성자·날짜가 먼저 나온다.
- 읽기 폭이 좁고 사이드바가 없어 집중하기 쉽다.
- 본문 이미지가 문맥 속에서 필요한 시점에만 등장한다.

### 채널톡 블로그 — 카테고리와 검색 구조

출처: https://channel.io/kr/blog

![채널톡 블로그](./references/05-channel-blog.png)

가져올 점:

- 카테고리와 검색이 항상 보이고 현재 위치가 명확하다.
- 대표 글 한 개와 후속 카드들을 한 화면에서 확인할 수 있다.
- 제목, 설명, 날짜, 작성자가 일관된 순서로 반복된다.

장편한외과에는 좌측 메뉴를 그대로 쓰기보다 데스크톱에서는 상단 필터, 모바일에서는 가로 스크롤 칩으로 단순화한다. 카테고리는 5개 안팎으로 제한한다.

### flex AX 허브 — 일관된 커버 시스템

출처: https://flex.team/blog

![flex 블로그](./references/06-flex-blog.png)

가져올 점:

- 카테고리별 색과 커버 규칙이 일관되어 콘텐츠가 쌓여도 정돈돼 보인다.
- 텍스트가 이미지 안에 들어갈 때도 로고 위치, 여백, 타입 크기가 일정하다.

장편한외과에는 검은 배경이나 강한 형광색 대신 따뜻한 오프화이트와 병원 브랜드 색상을 사용한다. 질환 카테고리별로 색을 바꾸기보다 아이콘·작은 라벨만 구분한다.

### 모두싸인 블로그 — 브랜드와 콘텐츠의 연결

출처: https://blog.modusign.co.kr/

![모두싸인 블로그](./references/10-modusign-blog.png)

가져올 점:

- 대표 콘텐츠를 이미지와 제목의 2단 구성으로 보여준다.
- 인사이트, 서식, 서비스, 고객 인터뷰처럼 콘텐츠 목적이 메뉴에 드러난다.
- 본 서비스 홈페이지와 블로그의 브랜드가 분리되지 않는다.

장편한외과도 블로그를 별도 매체처럼 만들기보다 병원 안내·의료진·방문 정보와 자연스럽게 연결해야 한다.

## 3. 랜딩페이지 레퍼런스

### 그리팅 — 한 문장, 두 행동, 하나의 증거

출처: https://www.greetinghr.com/

![그리팅 랜딩](./references/07-greeting-home.png)

가져올 점:

장편한외과의 주요 행동은 `전화 문의`와 `오시는 길` 두 개로 제한하고, 온라인 예약이 실제 운영될 때만 세 번째 행동으로 둔다.

### 토스 — 쉬운 언어와 일관된 섹션 리듬

![토스 랜딩](./references/08-toss-home.png)

가져올 점:

- 시각 자산의 스타일이 사이트 전체에서 일관된다.

장편한외과에는 3D 그래픽 대신 실제 공간 사진과 절제된 의료 일러스트를 사용한다.

### 나만의닥터 — 모바일 행동과 증거 제시

출처: https://my-doctor.io/

![나만의닥터 랜딩](./references/09-mydoctor-home.png)

가져올 점:

- 모바일 중심의 한 열 구조와 큰 행동 버튼
- 회원 수, 평점, 수상 등 증거를 CTA 바로 옆에 배치

장편한외과 모바일에서는 화면 하단에 `전화`와 `길찾기`를 고정하되 콘텐츠를 가리지 않게 높이를 제한한다.

## 4. 피해야 할 병원 홈페이지 패턴

![인천세종병원 화면](./references/12-avoid-sejong-density.png)

- 로고, 검색, 대표번호, 배너, 예약 카드, 퀵메뉴를 첫 화면에 모두 넣는 방식
- 금메달, 인증, 수상, 배너를 모두 같은 강도로 보여주는 방식
- 우측 고정 메뉴와 하단 고정 메뉴를 동시에 사용하는 방식
- 프로모션 팝업이 병원 소개보다 먼저 보이는 방식
- “파란색 + 둥근 카드 + 의료 아이콘”만으로 병원 정체성을 대신하는 방식

## 5. 장편한외과용 디자인 원칙

### 원칙 1. 그래픽보다 실제 병원이 먼저 보인다

홈 첫 화면에는 실제 외관 또는 진료 공간 사진을 사용하고, 의료진 사진은 작은 아바타가 아니라 최소 상반신이 보이는 크기로 사용한다. 실제 자산이 없을 때는 거대한 추상 모티프를 만들지 말고 타이포그래피 중심의 중립 레이아웃을 사용한다.

### 원칙 2. 한 화면에는 한 가지 판단만 요구한다

홈 첫 화면은 “어떤 병원인지”, 건강정보 첫 화면은 “무슨 글을 읽을지”, 글 상세 첫 화면은 “이 글이 내 증상과 관련 있는지”에만 집중한다.

### 원칙 3. 의료 신뢰는 장식이 아니라 출처와 맥락으로 만든다

검토 의료진, 검토일, 참고 출처, 바로 진료가 필요한 증상을 콘텐츠 안에서 분명히 보여준다. 인증·수상은 많아도 첫 화면에서 두 개 이상 강조하지 않는다.

### 원칙 4. 병원별 테마는 색상 교체가 아니라 자산·문장·사진의 조합이다

병원마다 로고, 진료 철학, 대표 의료진, 실제 공간, 대표 진료 분야가 달라야 한다. 플랫폼 공통 요소는 본문 폭, 카드 구조, 접근성, 컴포넌트 규칙에만 남긴다.

## 6. 화면별 반영안

| 화면 | 참고할 레퍼런스 | 장편한외과 반영 |
|---|---|---|
| 홈 히어로 | 차움 + 루닛 + 그리팅 | 실제 공간 사진, 한 문장 진료 약속, 전화·길찾기 2개 CTA, 오늘 진료 상태 |
| 빠른 진료 안내 | 차움 | 치핵·치루·치열·대장내시경 등 4~6개 진료 항목과 증상 연결 |
| 건강정보 목록 | 토스 테크 + 채널톡 | 대표 글 1개와 최신 글 3개를 첫 화면에 노출, 카테고리 5개 이하 |
| 콘텐츠 커버 | flex + 모두싸인 | 질환별 일관된 이미지 규격, 로고·텍스트 안전 영역, 추상 플레이스홀더 제거 |
| 글 상세 | 토스 테크 + 서울아산병원 | 제목·핵심 답변 우선, 720~760px 읽기 폭, 출처·검토 정보, 증상별 다음 행동 |
| 모바일 CTA | 나만의닥터 | 전화·길찾기 2개만 하단 고정, 본문과 겹치지 않게 처리 |

## 7. 제안하는 페이지 구조

### 홈

1. 로고와 최소 메뉴
2. 실제 병원 이미지 + 한 문장 진료 철학
3. 오늘 진료시간 + 전화 + 길찾기
4. 증상에서 시작하는 진료 안내
5. 이번 주 건강정보와 많이 읽는 글
6. 대표 의료진과 진료 원칙
7. 실제 병원 공간
8. 지도·주차·대중교통

### 건강정보

1. 짧은 제목과 검색
2. 증상·질환 카테고리
3. 대표 글 1개
4. 최신 글 3열 카드
5. 많이 읽는 글과 시리즈

현재처럼 큰 소개 영역과 거대한 추상 대표 이미지는 사용하지 않는다.

### 글 상세

1. 카테고리와 제목
2. 3줄 핵심 답변
3. 검토 의료진·검토일·출처
4. 필요한 경우에만 낮은 높이의 커버 이미지
5. 목차
6. 본문
7. 바로 진료가 필요한 신호
8. 관련 진료·전화·길찾기

## 8. 시스템 차원의 반영 전략

### 병원 온보딩에 추가할 데이터

- 로고 원본과 흑백·반전 버전
- 대표색과 보조색 또는 로고에서 추출한 후보색
- 대표 의료진 세로 사진
- 외관 1장, 내부 3장 이상
- 대표 진료 분야 3~6개
- 병원의 한 문장 진료 철학
- 전화, 길찾기, 주차, 진료시간
- 검증 가능한 경력·수치·인증

### 병원별 테마 모델

- `brand`: 로고, 색상, 문장 톤
- `photography`: 실제 사진 우선순위와 크롭 위치
- `content_cover`: 사진형, 의료 일러스트형, 타이포형
- `density`: 기본은 여유 있는 에디토리얼 밀도
- `conversion`: 전화, 길찾기, 예약 중 실제 운영되는 행동만 노출

### 콘텐츠 발행 품질 게이트

- 제목과 요약이 첫 화면에서 잘리지 않는지
- 문장이 완결되고 의료 수치의 의미가 분명한지
- 커버 이미지에 과도한 빈 공간이나 잘린 텍스트가 없는지
- 검토 의료진·검토일·출처가 있는지
- 모바일에서 전화·길찾기 버튼이 본문을 가리지 않는지

## 9. 구현 우선순위

### 1차: 즉시 체감되는 변경

- 건강정보 목록 상단 높이 축소
- 거대한 추상 모티프 제거
- 글 상세에서 제목과 핵심 답변을 커버보다 위로 이동
- 반복되는 우측 병원 정보 축소

### 2차: 병원별 고유성

- 온보딩 브랜드·사진 자산 모델 추가
- 실제 사진 기반 홈 히어로와 병원 갤러리
- 로고 기반 테마 토큰 생성과 운영자 승인

### 3차: 콘텐츠 시스템

- 커버 템플릿 3종과 크롭 규칙
- 증상·질환·상황 기반 콘텐츠 분류
- 발행 전 문장·출처·이미지 자동 검수

### 4차: 구조 안정화

- 중복 전역 CSS 제거
- 공통 레이아웃과 병원별 테마 분리
- 모바일, 키보드, 스크린리더, 색 대비 QA

## 최종 추천

홈은 차움의 실재감과 루닛의 절제된 전문성을, 건강정보는 토스 테크의 편집 구조를, 상세 글은 토스 테크의 읽기 경험과 서울아산병원의 의료 정보 분류를 결합한다. 전환 장치는 그리팅처럼 두 개의 명확한 행동만 남긴다.

이 조합이면 장편한외과가 스타트업 템플릿처럼 가벼워 보이지 않으면서도, 기존 병원 홈페이지처럼 복잡하고 낡아 보이는 문제를 피할 수 있다.
