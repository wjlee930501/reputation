# Re:putation 화면 전수 시각 감사

검수일: 2026-07-22  
검수 환경: Aside Browser + CUA, desktop 1440×900, tablet 768×1024/721×900, mobile 390×844  
범위: Admin 14개 화면, 공개 랜딩/정책, 3개 병원 홈, 진료·의료진·방문·콘텐츠 목록/상세

## 결론

공개 병원 허브의 데스크톱 첫인상과 사진 중심 에디토리얼 구성은 완성도가 높다. 가장 큰 개선 기회는 Admin 모바일의 화면 점유·좌우 잘림, 반복적인 운영 화면의 과도한 세로 길이, 그리고 공개 콘텐츠 본문 제목 중복이다. 공개 허브는 카드와 본문 반응형은 안정적이지만 모바일 공통 메뉴와 데이터 길이에 따른 히어로 비율을 보완해야 한다.

## P0 — 먼저 수정할 항목

### 1. Admin 모바일 상단 구조가 첫 화면의 약 65%를 점유

- 390×844에서 전역 Admin 헤더가 약 228px, 병원 헤더와 탭까지 합치면 실제 페이지 내용 시작점이 약 y=545다.
- 첫 화면에서 사용자가 작업 내용보다 로고·전역 메뉴·로그아웃·병원 메타·진행 상태·탭을 더 오래 보게 된다.
- 병원별 모든 화면에 반복되므로 누적 영향이 가장 크다.

권장:

- 모바일 전역 헤더를 56px 단일 행으로 축약하고, 신규 병원/상담 리드/로그아웃을 메뉴 시트로 이동한다.
- 병원 헤더는 병원명 + 상태 + 현재 화면 선택만 우선 노출하고 도메인·플랜·4개 진행 상태는 펼침 영역으로 이동한다.
- 페이지 본문이 y=180~220 이내에 시작하도록 목표를 둔다.

근거 캡처: `visual-audit-admin-dashboard-mobile.png`, `visual-audit-admin-onboarding-mobile.png`

### 2. Admin 모바일 핵심 정보가 실제로 좌우 잘림

- 병원 탭의 `리포트` 우측 좌표가 422px로 390px 화면 밖에 있다.
- 온보딩 단계 목록: 폭 460px, 우측 492px.
- 프로파일 DNS 표: 폭 581px, 우측 639px.
- 운영 기준 요약: 코드상 `min-w-[480px]`, 실제 우측 512px.
- 환자 질문 목록: 우측 449px.
- 병원 목록 표: 코드상 `min-w-[980px]`; 리포트 표도 약 466px로 액션이 잘린다.

권장:

- 모바일에서 모든 `min-width` 기반 표/그리드를 제거한다.
- 병원 목록·리포트·DNS는 행을 카드 또는 key/value 블록으로 변환하고 복사/검수 액션을 하단 전체 폭으로 둔다.
- 병원 화면 전환은 가로 탭 대신 현재 화면을 표시하는 선택 메뉴를 사용한다.
- 온보딩 단계는 가로 진행률 + 현재 단계 카드로 축약한다.

근거 캡처: `visual-audit-admin-hospitals-mobile.png`, `visual-audit-admin-profile-mobile.png`, `visual-audit-admin-essence-mobile.png`, `visual-audit-admin-query-targets-mobile.png`, `visual-audit-admin-reports-mobile.png`

### 3. 발행 콘텐츠 10개 중 5개에서 H1 제목이 본문에 다시 반복

- 화면 상단의 문서 제목 뒤, 본문 시작 위치에 같은 H1이 다시 나타난다.
- 대표 글에서는 첫 H1이 y≈634, 두 번째 H1이 y≈1,136에 모두 보인다.
- 시각적으로는 같은 제목을 두 번 읽게 되고, 문서 계층과 검색/AI 해석에도 좋지 않다.

권장:

- 생성 단계에서 본문 첫 H1을 금지한다.
- 렌더 단계에서도 `content.title`과 같은 첫 번째 Markdown H1은 제거하는 방어 로직을 둔다.
- 본문 소제목은 H2부터 시작하도록 검증한다.

근거 캡처: `visual-audit-site-jang-content-detail-desktop.png`, `visual-audit-site-content-duplicate-h1-desktop.png`

### 4. 환자 질문 화면이 운영 단위에 비해 지나치게 길고 반복적

- 데스크톱 문서 높이 약 5,514px, 모바일 약 12,521px.
- 12개 질문마다 메타 정보, 플랫폼, 실제 질문 문구, 추가 입력, 상태 제어가 반복된다.
- 중요한 우선순위와 이상 상태를 찾기 어렵고, 모바일에서는 좌우 잘림까지 겹친다.

권장:

- 기본 화면은 `우선순위 / 질문명 / 운영 문구 수 / 최근 측정 / 상태`만 보이는 압축 목록으로 만든다.
- 한 번에 하나의 질문만 accordion 또는 우측 detail panel에서 편집한다.
- 검색·상태·플랫폼 필터를 sticky toolbar로 두고, 저우선순위는 기본 접힘 처리한다.

근거 캡처: `visual-audit-admin-query-targets-desktop-top.png`, `visual-audit-admin-query-targets-desktop-mid.png`, `visual-audit-admin-query-targets-mobile.png`

## P1 — 구조와 비율 개선

### 5. 프로파일과 온보딩의 데스크톱 폭 사용이 비효율적

- 프로파일은 약 704px 폭에 대부분의 필드가 쌓여 문서 높이가 약 5,042px이고, 우측 400px 이상이 비어 있다.
- 온보딩은 약 4,458px이며 왼쪽 단계 목록이 끝난 뒤에도 긴 빈 열이 계속된다.
- 모바일 높이는 각각 약 6,483px, 6,304px이다.

권장:

- 데스크톱 12-column 기준으로 폼 8, 상태/미리보기 4 비율을 사용한다.
- 주소·연락처, URL, 원장 정보처럼 관련 필드를 2열 section grid로 묶는다.
- 온보딩 stepper는 sticky로 유지하되 콘텐츠와 같은 높이를 강제하지 않는다.
- 저장 버튼과 오류 요약은 sticky footer/action bar로 제공한다.

### 6. Admin 콘텐츠 상태 카드 6개가 모두 같은 시각적 무게

- 자동 발행 대기/차단, 생성 대기, Slack 재시도, 검수 대기/완료가 모두 상단에서 경쟁한다.
- 실제로 지금 처리해야 할 상태가 무엇인지 한눈에 구분되지 않는다.

권장:

- 상단에는 가장 긴급한 1개 상태와 CTA만 크게 둔다.
- 나머지는 `생성 / 안전검사 / 발행 / 알림 / 검수` 파이프라인으로 묶고 정상 상태는 축약한다.
- 색은 의미를 갖는 3단계(차단/주의/정상)로 제한한다.

근거 캡처: `visual-audit-admin-content-desktop.png`, `visual-audit-admin-content-mobile.png`

### 7. 공개 허브 모바일 공통 메뉴의 마지막 항목이 잘린 상태로 시작

- 390px에서 `공식 홈페이지`의 우측이 411px로, 21px가 화면 밖에 있다.
- 내부 가로 스크롤은 가능하지만 현재 화면에는 스크롤/더보기 안내가 없다.
- 세 병원 모두 같은 공통 헤더를 사용하므로 한 번의 수정으로 해결 가능하다.

권장:

- 4개 내부 메뉴는 유지하고 외부 홈페이지를 `더보기` 또는 상단 외부 링크로 분리한다.
- 가로 스크롤을 유지하면 오른쪽 fade/peek와 현재 메뉴 강조를 제공한다.
- 721px 태블릿 경계와 768px에서는 메뉴가 정상적으로 맞는다.

### 8. 병원별 긴 문구에 따라 모바일 히어로 비율이 크게 흔들림

- 장편한외과는 첫 제목이 비교적 안정적이다.
- 연세속시원내과와 행복드림의원은 제목이 6~7줄이 되어 첫 화면 대부분을 차지한다.
- 모바일 제목이 `clamp(32px, 10.2vw, 40px)`라 390px에서 거의 40px로 렌더링된다.

권장:

- 모바일 제목을 32~36px, line-height 1.12~1.16 범위로 낮춘다.
- 진료과 나열이 길면 핵심 2개 + 보조 태그로 분리한다.
- 이미지가 첫 화면 하단에 최소 20~25% 보이도록 hero copy의 최대 높이를 관리한다.

근거 캡처: `visual-audit-site-jang-home-mobile.png`, `visual-audit-site-yeonse-home-mobile.png`, `visual-audit-site-haengbok-home-mobile.png`

### 9. 공개 홈과 콘텐츠 상세의 세로 길이가 매우 큼

- 병원 홈: 데스크톱 약 6,874~7,503px, 모바일 약 10,136~12,297px.
- 콘텐츠 상세 대표 글: 데스크톱 약 5,356px, 모바일 약 9,681px.
- 정보량은 AI/검색 목적에 맞지만 환자 탐색 흐름에는 피로가 크다.

권장:

- 홈 상단에 `진료 / 의료진 / 건강정보 / 방문` 인페이지 목차를 둔다.
- 각 긴 섹션은 3~4개만 먼저 보여주고 전체 목록으로 연결한다.
- 콘텐츠 상세에는 읽기 진행률과 H2 기반 목차를 제공한다.
- 모바일에서는 긴 breadcrumb, byline, trust 정보를 2줄 요약 + 펼침으로 압축한다.

### 10. Admin 대시보드와 긴 표의 스캔성이 낮음

- 대시보드는 약 3,904px, 모바일 약 8,158px.
- 하단 환자 질문 표의 글자가 작고 행 구분이 약해 우선순위 비교가 느리다.

권장:

- 첫 화면은 `현재 상태 / 이번 주 할 일 / 주요 이상` 3영역으로 제한한다.
- 추이·질문 단위 진단은 별도 섹션에서 기본 접힘 또는 탭으로 둔다.
- 숫자는 tabular, 본문 13~14px 이상, 행 높이 48px 이상을 유지한다.

### 11. 랜딩의 핵심 증거 패널이 첫 화면에서 다소 희미함

- AI 답변 패널은 구조와 탭 동작은 좋지만 회색·흰색 비중이 높아 비활성 placeholder처럼 보인다.
- 모바일에서는 제품 증거가 첫 화면 하단에 늦게 나타난다.

권장:

- AI가 병원을 선택하는 이유와 근거 출처 블록의 명도/테두리를 한 단계 강화한다.
- 모바일에서 보조 문구를 줄여 패널 상단 일부가 첫 화면 안에 더 빨리 보이게 한다.
- 탭 전환 시 panel 높이는 369~390px로 바뀌지만 hero 전체 높이 695px는 유지되어 layout shift는 없었다. 이 동작은 유지한다.

근거 캡처: `visual-audit-site-landing-desktop-top.png`, `visual-audit-site-landing-mobile-top.png`

### 12. 랜딩의 작은 회색 텍스트 대비 보완

- `.ai-panel-disclaimer` 12px, `.hero-eyebrow` 13px가 흰 배경에서 대비 약 3.25:1이다.
- 일반 크기 텍스트 권장치 4.5:1에 못 미친다.

권장:

- 해당 텍스트를 최소 `#6b7280` 수준으로 진하게 하거나 14px 이상으로 올린다.
- helper text는 12px/18px 아래로 내려가지 않도록 토큰화한다.

## P2 — 다듬기

### 13. 병원 목록/신규 병원/스케줄 화면의 데스크톱 여백이 목적 없이 남음

- 신규 병원은 약 704px, 스케줄 폼은 약 448px에 고정되어 오른쪽이 크게 빈다.
- 병원 목록과 리포트도 데이터가 적을 때 넓은 빈 공간만 남는다.

권장:

- 신규 병원 우측에 전체 단계와 자동 생성 결과 미리보기를 둔다.
- 스케줄 우측에 이번 달 달력과 예상 콘텐츠 배분을 즉시 표시한다.
- 빈 공간을 억지로 채우기보다 `max-width`를 명시해 의도된 집중 레이아웃처럼 보이게 한다.

### 14. Admin 보조 텍스트가 10~12px에 자주 의존

- 대비는 대체로 확보되어 있으나 긴 설명과 상태가 작은 글자에 몰려 운영 피로가 생긴다.

권장:

- 운영상 중요한 helper는 12/18, 표 본문은 13/20, 일반 본문은 14/22 이상으로 통일한다.
- 10~11px는 버전, 보조 배지, 비핵심 메타만 사용한다.

### 15. 빈 상태의 다음 행동을 더 구체화

- 진료 상세의 `관련 의료 정보가 준비 중입니다`, 노출 보완 0건, 리포트/리드 빈 상태는 시각적으로는 정돈되어 있다.
- 다만 다음 단계가 한 가지 문장이나 버튼에만 의존한다.

권장:

- 운영 화면 빈 상태에는 `왜 비어 있는지 / 무엇을 하면 채워지는지 / 예상 결과` 3줄을 제공한다.
- 공개 진료 상세는 관련 글이 없더라도 상담 CTA, 동일 카테고리 FAQ 2~3개를 연결한다.

## 유지할 장점

- 병원 홈의 사진 중심 44/56 데스크톱 히어로와 정보 rail은 신뢰감이 좋다.
- 공개 모바일 하단의 전화/진료시간/진료안내/길찾기 action bar는 환자 목적에 잘 맞는다.
- 랜딩 탭, 콘텐츠 필터, Admin 운영 설정 드롭다운은 실제 조작에서 정상 동작했다.
- Admin 운영 설정 드롭다운은 모바일에서 약 320×280으로 화면 안에 맞는다.
- 랜딩의 scroll reveal과 AI 답변 모션은 `prefers-reduced-motion`을 존중한다.
- 공개 화면은 390px에서 문서 전체의 가로 overflow가 발생하지 않았고, 본문 카드 반응형은 전반적으로 안정적이다.
