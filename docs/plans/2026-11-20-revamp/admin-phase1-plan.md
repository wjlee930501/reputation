## 1. PR 나누기

작은 PR 여섯 개. 앞의 셋은 서로 독립이고 화면 문구 위주라 먼저 낸다. 4~6은 백엔드 API가 붙는다.

### PR 1 · 문구 정리(영문 코드·시험 운영·첫 연락 기한·지역 통계 문구)
- `CONDITION_LABELS`에 8개 키 한글 라벨, `HUMAN_CONDITIONS`에 주소·전화·진료 항목·병원명·slug 추가. 모르는 키는 영문 대신 「확인 필요 항목」으로.
- 보고서 경고 코드 → 한글(`report-warning-labels.ts` 한 곳): `LEGACY_REPORT_UNVERIFIED` → 「이전 방식 보고서 · 미검증」, `MANIFEST_*`·`MEASUREMENT_*` 등. 모르는 코드는 「확인 필요」.
- `actor-display.ts`에 `system:*` 표(AI 자동 검토·AI 자동 교정·자동 발행·자동 운영 기준·원장 설문·도입문의 접수 …) — 모르는 `system:` 값은 「자동 처리」. 콘텐츠 상세·상담 요청·보고서 고치기를 이 함수로.
- `hospital_overview._remaining`이 모르는 키에 500 대신 기본 라벨(백엔드 한 줄 + 테스트).
- 「시험 운영」 배지·하단 「시험 운영」 글자 삭제.
- 상담 요청 첫 연락 기한 표시·기한 순 정렬·기한 초과 카드 삭제(삭제 확정). 정렬은 접수 최신순.
- 레이아웃 지역 통계 문구: 「{시·도} 다른 공개 병원 {N}곳(이 병원 제외)」.
- 병원 목록 「사진 승인 대기」 → 「공개 페이지 항목 입력 필요」(로고·대표색·첫 화면 문구). 승인 단계를 새로 만들지 않는다.
- 테스트 데이터: 상담 요청 목록 기본에서 운영 점검용(`is_operations_test`) 숨김 + 「테스트 포함」 보기. 운영자 계정의 운영 점검 계정은 접힌 묶음으로. 운영 점검 표지가 없는 실제 접수(예: `[테스트] 알림점검의원`)는 코드로 가릴 수 없어 운영 데이터 결정으로 남긴다.
- 백엔드 「확인 필요」 필터(신규 또는 24시간 지나도 미연락)는 그대로 둔다. 화면에서 기한 글자·순서만 없앤다.

- 공용 `DangerMenu`(⋯) + `ConfirmDialog`(병원명 재입력이 필요한 것만 입력 칸).
- 병원 일시정지: 머리글 ⋯ 안 + 병원명 재입력. 재개는 확인창만.
- 상담 요청 개인정보 파기: ⋯ 안 + 병원명 재입력.
- 비공개 후 재생성: ⋯ 안으로 이동, 기존 사유 입력 확인창 유지.
- 계정 정지: ⋯ 안 + 확인창(이메일 재입력). 활성화는 확인창만.
- 비용 전체 중지: 확인창(「전체 중지」 입력). 해제는 확인창만.
- 쓰기는 지금처럼 `fetchAPI` → BFF actor 단언 경로 그대로.

### PR 4 · 보고서 탭
- 요약 숫자: 기간·종류별 최신 판만 센다. 목록 API가 24행으로 잘리므로 서버에서 최신 판을 고른 집계를 내준다(`GET …/reports/summary`, 쿼리 수 고정).
- 작업 카드: 같은 달·종류는 가장 최근 실행 1장만(최근 20건 안에서 화면이 묶는다 — 카드는 최근 3개 달만 보이므로 충분).
- 목록 각 행 「PDF」(원장 전달용, 검증된 판만) — **파일로 바로 저장**. 상세 창의 원장 PDF도 빈 새 탭 대신 파일 저장으로 바꾸되, **저장한 바로 그 바이트**의 hash를 계산하고 저장이 끝난 뒤에만 전달 기록 버튼을 연다(서버 hash 복사 금지). 다운로드 실패·판 변경·409 뒤 hash 초기화를 테스트로 묶는다. 목록에서 받은 파일은 hash를 남기지 않으므로 전달 기록은 상세 창에서 다시 받아야 한다고 화면에 적는다 — 목록에서 받은 파일로도 기록하게 할지는 결정 대기 7번.
- 「개발팀 문의 정보 복사」는 오류 상태에서만.

### PR 5 · 근거 자료 정리
- 「제외 자료 숨김」 기본 켜짐, 숨긴 자료는 「제외 자료 N건」 묶음 안에서 복원(`reinclude`).
- 자료 목록 처음 5개 + 더 보기.
- 근거 노트 「제외 자료로 표시」가 새로고침 뒤 사라지는 문제: 상세 API에 제외 노트 포함 옵션(`include_noise=true`)을 더하고 화면에서 표시·해제(백엔드 작은 변경).
- 영구 삭제는 4절 5번 결정 뒤.

### PR 6 · 메뉴·대시보드·병원 목록 (백엔드 집계 API)
- 메뉴: 대시보드(신규) · 병원 · 처리 목록 · 상담 요청 · 노출 진단 · 계약 등록 · 설정. **경로는 그대로**(`/hospitals`·`/operations`·`/leads`·`/diagnoses`·`/hospitals/new`·`/accounts`), 백엔드 딥링크 `_ADMIN_ROUTE_ROOTS` 영향 없음. 대시보드는 `/`(지금은 `/hospitals`로 보냄).
- 설정(`/accounts`): 운영자 계정 + 처리 목록에서 옮긴 「자동 작업 한도」(비용 안전장치).
- 처리 목록 배지: `is_operator_todo`를 통과한 사고의 원인 묶음 수(일일 요약 「사람의 일」과 같은 값). 문제·복구 큐 합계는 자동 복구 중인 맥락 행도 포함하므로 쓰지 않는다. 새 요약 API가 내준다(쉘이 9쿼리짜리 overview를 부르지 않게). 0이면 숨김. 요청서 예시(세 큐 합 16)와 다르다 — 사용자 확인.
- 새 API `GET /admin/dashboard/summary`(쿼리 수 고정): 상태 수(`hospital_states` 판정), 할 일 원인 묶음 수, 지난달 원장 보고 미전달 수(운영센터 보고서 큐 `DELIVERY_PENDING`), 상담 요청 수(운영 점검 제외), 이번 달 발행 합계.
- 병원 목록 새 칸: 공개 주소(지금 열리는 주소만 — 헤더·목록·콘텐츠·대시보드가 한 함수)·이번 달 발행 n/계획·AI 언급률·할 일. **값의 정의는 현황 탭과 같다**: 발행 = 현황 `_month_summary`(계약 월 기준, `carried_over_from` 우선, 계획 = 첫 달 안분·일정 반영 `resolve_month_target`), 언급률 = 최근 측정 주 값(없으면 「측정 전」, 0과 구분). 현황 계산을 병원 id 묶음 쿼리로 다시 써서 목록에 붙인다. 목록 쿼리 예산 테스트(지금 정확히 6)는 새 고정값으로 올리고 「병원 1곳 = 12곳」 비교를 유지한다. 대시보드 API도 같은 예산 테스트.
- 할 일 칸과 배지는 다를 수 있다(배지는 전체에서 원인을 묶고, 목록은 병원별로 묶는다). 대시보드에 그 말을 적는다. 공개 페이지 항목·준비 조건·미전달 보고서·일시정지는 할 일 숫자에 섞지 않고 따로 안내한다. 기본 목록은 운영 중+준비 중, 일시 정지는 아래 접힌 묶음, 필터 탭·정렬. 전체 수는 서버가 준다.
- 크기가 크면 6a(메뉴·설정·배지) / 6b(목록 칸) / 6c(대시보드)로 나눈다.

### PR 7 · 생성 품질 — 메모체 필수 문구(운영 확인 완료)
- 행복드림 11.02 글 「소아 탈수, 어느 전문의를…」의 `…즉시 상태 확인이 필요함.`·`…순서를 지켜야 함.`은 **필수 문구**다. 운영 Admin(읽기 전용)에서 확인: 행복드림의 현재 적용 판은 **v9(2026-08-31, 옛 AI 승인본, D33 이전)**이고 필수 문구 9개 중 2개가 메모체(…함)다. 10-30 생성 때 브리프 `must_use_messages`에 그대로 실렸고, 원문 그대로 넣기 규칙(`must_use_verbatim`)이 문장을 바꾸지 못하게 한다. 대기 중인 v10 초안은 메모체가 4개로 늘었다.
- 자동 판(D33)은 「다·요·죠」로 끝나는 원장 문장만 고르고 소비할 때도 다시 거르지만, **옛 승인본은 소비 단계에서 이 규칙을 거치지 않는다**(`must_use_verbatim.must_use_requirement` — `automatic_version_verbatim_texts`가 자동 판에만 값이 있다).
- 제안(계약 안): 소비 단계에서 옛 승인본 문구에도 `essence_claims.is_not_doctor_statement`(서술어 종결·질문·안내문 제외)를 적용해, 메모체·명사구 문구는 필수 문구에서 빼고 `must_use_exclusions`에 남긴다. 필수 문구 원문 규칙(15번)은 그대로이고, 원장의 완결된 문장만 원문 그대로 남는다. 이미 공개된 글은 바꾸지 않는다(새 글부터).
- 영향 범위: 옛 승인본으로 운영 중인 병원(배포 B 이전 9곳 중 아직 자동 판으로 넘어가지 않은 곳). 배포 전 병원별로 빠질 문구 수를 읽기 전용으로 센다.
- 대안: 그 병원들을 자동 판으로 옮기는 백필(`essence_autonomy_backfill --ids`, 운영 조치 — 사용자 결정).
- 자료 머리말 삽입 사례는 아직 못 찾았다 — 마케팅에 글 주소를 받는다.
