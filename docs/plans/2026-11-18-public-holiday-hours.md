# 공휴일 진료시간 — 구현과 특정 날짜 진료 설계안 (2026-11-18)

요청: 마케팅팀(365서귀포삼성정형외과의원 원장님 요청, 전 병원 공통 기능). 병원 이름의 '365' 때문에 AI가
연중무휴로 오해한다. 공개 페이지 JSON-LD `openingHoursSpecification`에 공휴일 정보가 없다.

## 이번에 구현한 것 — 공휴일 칸

- **저장**: `hospitals.business_hours`(JSON) 안에 요일 키와 같은 문자열 키 `holiday`를 하나 더 둔다.
  값은 `휴진` 또는 `09:00 ~ 13:00`. 마이그레이션 없음. 문자열이라 공개 payload 검증
  (`isNullableStringRecord`)과 기존 파서(`isClosedLabel`·`extractTimeRanges`)가 그대로 받는다.
  Admin이 보내지 않으면(옛 화면) 저장된 값을 건드리지 않는다(`exclude_unset`).
- **Admin**: 병원 정보 > 진료시간의 요일 칸 아래에 `공휴일` 칸과 `휴진` 버튼. 비우면 공휴일 정보가 나가지 않는다.
- **JSON-LD**: `dayOfWeek: https://schema.org/PublicHolidays`. 휴진이면 다른 휴진 요일처럼 `opens/closes 00:00`,
  시간이면 그 시간. 값이 비면 항목을 만들지 않는다.
- **화면**: 요일별 표(/visit)·주간 진료시간(기본 레이아웃)·A/C 레이아웃 목록·llms.txt에 `공휴일` 행.
  첫 화면 넷째 칸은 7일 같은 시간 + 공휴일 휴진이면 `휴무일 · 공휴일`(이전에는 `연중무휴`).
  공휴일 값이 없는 병원은 종전처럼 `연중무휴`다.
- **완료 판정**: 공휴일 값만으로는 진료시간 요건을 채운 것이 아니다(요일 시간이 하나는 있어야 한다).
- **배포 순서**: Backend(API) 먼저, 그다음 Admin·Site. 옛 API는 `holiday`를 모르는 키로 버린다.

## 남은 한계

- 오늘이 공휴일인지 모른다(공휴일 달력이 없다). 공휴일 당일에도 첫 화면 '오늘 진료'는 그 요일 시간을 보인다.
- 공휴일 값이 없는 7일 진료 병원은 여전히 `연중무휴`로 보인다 — 실제로 공휴일에 쉬는 병원은 값을 넣어야 한다.

## 설계안만 — 특정 날짜 진료(`specialOpeningHoursSpecification`)

구현하지 않았다. 날짜가 지나면 사라져야 하고, 목록 편집 UI와 공개 표면 캐시 갱신이 필요해 범위가 크다.

- **저장**: 새 열 `hospitals.special_hours`(JSONB, NULL 허용, 마이그레이션 0097) —
  `[{"date": "2026-12-25", "value": "휴진", "note": "성탄절"}]` 또는 기간 `{"from", "through"}`.
  `business_hours`에 섞지 않는다 — 문자열만 받는 공개 payload 검증과 진료시간을 그대로 싣는 콘텐츠·검수
  프롬프트가 깨진다.
- **검증**: 날짜 형식, 값 100자, 의료광고 필터, 최대 30건, 지난 날짜는 저장 때 버린다.
- **JSON-LD**: `specialOpeningHoursSpecification`에 `validFrom`·`validThrough`(같은 날이면 같은 값),
  휴진은 `opens/closes 00:00`. 오늘(KST) 이전 항목은 내보내지 않는다.
- **화면**: /visit 표 아래 '특별 진료 안내' 목록(앞으로 30일). 오늘이 그 날이면 첫 화면 '오늘 진료'가
  그 값을 쓴다(공휴일 달력 없이도 '오늘 휴진'을 맞힐 수 있는 유일한 경로).
- **캐시**: 공개 페이지 HTML은 오래 캐시된다. 날짜가 지나면 지난 항목이 남지 않게 매일 00:05 KST에
  특별 진료가 있는 병원만 `SITE_REVALIDATION` intent를 남긴다(또는 클라이언트에서 날짜를 다시 거른다).
- **Admin**: 진료시간 아래 '특정 날짜 진료' 목록(날짜 선택 + 휴진/시간 + 메모, 추가·삭제).
