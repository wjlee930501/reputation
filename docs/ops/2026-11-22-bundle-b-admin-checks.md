## 1. #377 배포 직후 — 운영 약속 편수가 바뀌는지 읽기 전용으로 본다

#377은 마케터가 첫 달 편수를 저장할 때 남기는 새 감사 표지(`operator_month_target`)가 있을 때만 판정이 달라진다. 배포 직후에는 그 표지가
없으므로 **배포만으로는 어떤 병원·달의 약속 편수도, 슬롯도 바뀌지 않아야 한다**. 당월 조정(21:30)과 월말 배치는 슬롯을 늘리기만 하고 줄이지
않는다 — 편수가 그대로면 배포 때문에 생기거나 사라지는 슬롯은 없다.

확인 스크립트는 [`snippets/first_month_target_impact.py`](snippets/first_month_target_impact.py)다. 새 판정(`month_content_target_sync`)과
옛 판정(같은 입력, 마케터 표지 무시)을 일정이 있는 모든 병원의 이번 달·다음 달에 대해 나란히 계산한다. `SET TRANSACTION READ ONLY` 뒤 롤백한다.
migrate Job 이미지(새 Backend)에서 돌려야 한다 — 새 판정 함수가 그 이미지에만 있다.

```bash
B64=$(base64 < docs/ops/snippets/first_month_target_impact.py | tr -d '\n')
```

```bash
gcloud run jobs execute reputation-migrate --project mso-platform-481505 --region asia-northeast3 --wait --args=python,-c,"import base64;exec(base64.b64decode('$B64'))"
```

gcloud `--args`는 쉼표로 인자를 나눈다 — 위 한 줄에는 쉼표가 없다(base64 안에도 없다). 결과는 Job 로그의 JSON 한 줄이다.

| 칸 | 배포 직후 기대 | 다르면 |
|---|---|---|
| `operator_markers` | 0 | 누가 이미 편수를 저장했다. 그 병원·달은 `changed`에 나온다 — 의도한 저장인지 감사 로그(`set_schedule` detail의 `operator_month_target`)로 본다 |
| `changed` | `[]` | 표지 없이 판정이 달라졌다면 결함이다 — 그 병원의 21:30 당월 조정 전에 개발 확인 |
| `months[].new` vs `live` | `new ≥ live`가 보통 | `new > live`는 당월 조정이 채울 몫(배포 전과 같은 동작). `new < live`는 사람이 남긴 원고 등으로 이미 넘친 달 — 자동으로 줄이지 않는다 |

**마케터가 첫 달 편수를 실제로 저장한 뒤**: 같은 스크립트를 다시 돌리면 그 병원·달이 `changed`에 `new`(정한 편수) · `legacy`(옛 판정)로 나온다.
줄였으면 그 저장의 감사 detail `operator_month_target.cancelled_ids`가 종료한 슬롯이고 `live`가 `new`와 같아야 한다.
늘렸으면 `live`가 `new`까지 찬다(종료했던 슬롯은 세지 않고 새로 만든다).

**롤백 주의**: 옛 Worker는 이 표지를 모른다 — 마케터가 줄인 달이 있으면 옛 판정(`legacy`)으로 돌아가 보고서·계약 이행 집계·일일 SLO가 그 달을
계약 편수로 보고 「미달」로 표시한다. 슬롯은 더 생기지 않는다(남은 편수 계산이 종료한 슬롯까지 행 수로 센다). 롤백 전에 이 스크립트로 `changed`를 남긴다.

## 2. 운영 어드민에서 볼 것 — 로그인 뒤 무엇을 누르나

쓰기는 실제 운영 데이터를 바꾼다. **표시만 확인하고 저장·등록은 누르지 않는다**(아래 「저장해 보려면」은 일부러 시험할 때만).

### #383 처리 목록 「오늘의 운영」 탭 삭제
1. 왼쪽 메뉴 **처리 목록**(`/operations`).
2. 탭이 **신규·온보딩 · 월간 보고서 · 문제·복구** 셋이고 **문제·복구가 선택돼** 열리는지.
3. 주소창에 `/operations?queue=today` — 위에 「오늘 발행 예정 글을 보고 있습니다(발행 정지 경보에서 연 화면)」 안내와 **문제·복구로** 단추가 보이는지.

### #384 계약 등록 「계약 시작일(첫 발행 기준)」
1. **병원** → **신규 병원 온보딩**(`/hospitals/new`).
2. 담당 AE 아래에 **계약 시작일(첫 발행 기준)** 날짜 칸과 안내(「…준비가 끝난 뒤 이 날짜와 그다음 날 중 늦은 날부터…」)가 보이는지. 비워 두면 등록한 날이다.
3. **계약 등록은 누르지 않는다.**
4. (#371, 묶음 A) 상담 요청에서 계약 등록으로 들어오면(`/hospitals/new?leadId=…`) 사이트 레이아웃 카드 하나에 「추천 · {시·도}에서 가장 적게 쓰는 틀」 표시와 미리 골라 두었다는 안내가 보이는지.

### #372 계약 종료일·「운영 종료」
1. 아무 병원이나 열고 머리글 오른쪽 **⋯** → **계약 종료일 기록**이 있는지(일시 정지 병원에도, 휴대폰 폭 머리글에도).
2. 눌러 날짜 칸이 있는 확인창이 뜨는지 본 뒤 **취소**.
3. **병원** 목록: 「운영 종료」 칩·묶음은 운영 종료 병원이 1곳 이상일 때만 보인다 — 지금은 계약 종료일을 기록한 병원이 없으므로 보이지 않는 것이 정상.
4. 저장해 보려면: 일시 정지 병원 하나에 **지난 날짜**를 저장 → 머리글 「운영 종료 · 계약 종료 YYYY-MM-DD」, 목록 아래 **운영 종료** 묶음, 대시보드 「공개 중」 카드의 「일시 정지 N(운영 종료 M)」.
   다시 ⋯ → 날짜를 비우고 저장하면 지워진다(감사 `set_contract_end` 두 줄이 남는다). 병원 상태·공개는 바뀌지 않는다.

### #377 발행 일정 「시작 달 발행 편수」
1. 병원 → **콘텐츠** 탭 → **콘텐츠 발행 일정** 펼치기.
2. 시작일의 달이 **계약 첫 달**(그 달 앞에 공개한 글이 없는 달)인 병원이면 시작일 아래에 **시작 달 발행 편수** 숫자 칸(「…편 / 계약 N편」)과 「지금 이 달 약속: N편」이 보이는지.
   이미 공개 글이 있는 병원은 칸 대신 「시작 달 발행 편수 N편 · 이 달은 계약 첫 달이 아니라 계약 편수를 따릅니다.」 한 줄.
3. 칸은 저장했을 때 적용될 값(마케터가 정한 값, 없으면 계약 편수)으로 채워져 있다. **손대지 않고 저장하면 지금 규칙(계약 편수) 그대로**다.
4. **저장은 누르지 않는다** — 일정 저장은 그 달 슬롯을 다시 배치한다. 시험하려면 첫 달 병원에서 편수를 줄여 저장한 뒤 1절의 스크립트로 확인한다.

### #370 노출 보완 제안 접기(묶음 A)
1. 병원 → **콘텐츠** 탭 맨 아래 — 「노출 보완 제안」이 **접힌 채** 제목 줄에 「N건 · 펼쳐 보기」(20건이면 「20건 이상」).
2. 옛 주소 `/hospitals/{id}/exposure-actions`로 들어오면 그 칸으로 내려가 **펼쳐져** 있는지.

### #363 의료진 사진 안내(이미 배포)
1. 행복드림 → **병원 정보** → 의료진 칸의 사진 선택 아래와 「사진과 사용 권리」의 원장 사진 줄.
2. 연결된 사진(원장 캐릭터 일러스트)에 「공개 페이지에는 이 사진이 의료진 사진으로 나가지 않습니다 — 캐릭터·일러스트로 분류된 사진입니다. 실제 원장 사진을 올려 연결하세요.」가 보이는지.
