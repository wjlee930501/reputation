# Admin 한국어 문구 안내

문서 버전: **1.0** · 갱신일: **2026-09-07 (Asia/Seoul)**

이 문서는 Re:putation Admin에서 운영자가 화면을 읽고 바로 다음 행동을 판단할 수 있도록 하는 문구 원칙이다. 화면 문구는 API의 내부 값이나 데이터 모델을 번역하는 일이 아니라, 저장된 상태와 운영 의미를 설명하는 일이다.

## 기본 원칙

- 상태는 **현재 상태 → 운영상 의미 → 필요한 행동** 순서로 짧게 쓴다. 자동으로 진행 중인 작업은 사람의 할 일처럼 표시하지 않는다.
- `PENDING`, `RUNNING`, `FAILED`, `UNKNOWN`, `PUBLISHED` 같은 enum과 API 필드명·URL·query 식별자는 코드 계약으로 유지한다. 화면에서만 설명을 붙인다.
- `0`, 미언급, 실패, 미확정, 비교 불가를 같은 말로 묶지 않는다. 확인하지 못한 값은 `확인되지 않음` 또는 `측정 결과 없음`으로 표시한다.
- `생성 완료`, `검수 완료`, `공개 완료`, `전달 완료`는 서로 다른 사건이다. 한 단계가 끝났다고 다음 단계가 끝난 것처럼 쓰지 않는다.
- 정상 자동 생성·측정·발행에는 확인 버튼이나 반복 알림을 추가하지 않는다. 사람의 행동은 계약 인수, 공식 정보·공개 주소 결정, 자동 검토가 해결하지 못한 예외, 고객 보고서 전달처럼 실제로 사람이 맡은 일에 한정한다.
- 원장용 보고 자료와 내부 운영 화면은 독자를 구분한다. 내부 오류 코드·명령어·검수 메모는 원장용 문구에 넣지 않는다.

## 자주 쓰는 표현

| 엔지니어 표현 | 화면에서 쓸 표현 | 사용 기준 |
|---|---|---|
| AI 노출 | AI 답변에서 병원이 언급되는 정도 | 기능 설명과 지표 제목에 사용 |
| AI 언급률 | 병원 언급률 | 측정 분모가 확정된 성공 답변일 때만 사용 |
| source / evidence | 근거 자료 / 근거 노트 | 원문 자료와 추출된 발췌를 구분 |
| observed at | 확인 시각 | 마지막 관측 시각이 운영 상태를 보증하지 않을 때 사용 |
| attribution | 연결 근거 | 콘텐츠와 측정 결과의 연결을 인과관계로 과장하지 않음 |
| pipeline / orchestration | 처리 흐름 / 자동 처리 | 내부 구현 흐름을 설명할 때만 사용 |
| profile | 병원 기본 정보 | URL·API 필드명은 그대로 둠 |
| lead | 상담 요청 | 고객 문의와 무료 진단 신청을 운영 화면에서 부르는 말 |
| workspace | 병원 운영 화면 | 병원별 내부 화면을 설명할 때 사용 |
| dashboard | 운영 요약 / 운영 현황 | 숫자보다 운영자가 해야 할 판단을 앞세움 |
| schedule | 발행 일정 | 월간 편수와 발행 요일을 설정하는 화면 |
| cohort / manifest | 측정 대상 묶음 / 월간 측정 목록 | 고객용 문구에는 내부 용어를 노출하지 않음 |
| artifact | 보고서 파일 | 실제 파일과 검증 상태를 함께 말할 때 사용 |

## 금지할 혼동

- 확인되지 않은 관측값을 `운영 중`, `완료`, `0%`로 바꾸지 않는다.
- 오류가 난 측정을 미언급으로 세지 않는다. 실패·미확정은 언급률 분모에서 빠진다는 사실을 명시한다.
- 보고서 파일을 만들었다는 사실을 원장에게 전달했다는 뜻으로 쓰지 않는다.
- 자동 작업 중인 항목에 `승인`, `확인`, `재시도`를 기본 행동으로 붙이지 않는다. 서버가 허용한 예외 행동이 있을 때만 표시한다.
- `AI가 판단했다`, `AI가 보증한다`, `노출을 보장한다`처럼 시스템이 실제로 보장하지 않는 결과를 약속하지 않는다.

문구를 바꿀 때는 해당 상태를 만드는 Backend/API 계약과 현재 화면의 다음 행동을 함께 확인한다. 내부 식별자·테스트 계약을 바꾸지 않고, 화면 문구와 접근성 라벨만 이 원칙에 맞게 고친다.
