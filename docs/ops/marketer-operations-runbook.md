# 마케터 운영 여정 안내서

이 문서는 개발 도구 없이 Admin과 Slack만으로 고객 인수부터 월간 보고까지 처리하는 순서입니다.
화면에 문제가 보이면 항상 `무슨 문제인지 → 고객 영향 → 지금 할 일`을 읽고, 안내된 버튼을 누릅니다.
안전하게 다시 실행할 버튼이 없으면 `개발팀 문의용 정보 복사`를 눌러 복사한 내용을 개발팀에 전달합니다.

## 1. 상담 요청 인수

1. `/leads`에서 새 상담 요청을 엽니다.
2. 같은 병원이 이미 등록됐는지 확인합니다.
3. 영업 담당자, 운영 담당자, 계약 번호, 계약 시작일, 요금제, 인수 처리 기한을 입력합니다.
4. `온보딩 시작`을 누르고 계약 인수 기록을 승인합니다.
5. 다른 운영자가 먼저 처리했다는 안내가 나오면 `상담 요청 다시 불러오기`를 누른 뒤 최신 상태에서 다시 판단합니다.

예상 상태: 계약 인수 승인 시각과 담당자가 보이고, 병원 온보딩 화면으로 이동할 수 있습니다.

## 2. 병원 온보딩

`/hospitals/{병원 ID}/onboarding`에서 화면 상단의 `지금 해야 할 일`을 한 단계씩 처리합니다.

1. 병원 필수 정보를 저장합니다.
2. 초기 진단 리포트를 확인합니다.
3. 공개할 병원 정보와 근거 자료를 확인합니다.
4. 콘텐츠 일정과 발행 요일을 저장합니다.
5. 공개 주소를 확인하고 운영 시작 상태로 전환합니다.

네이버 글 한 건을 가져오지 못했다면 해당 글의 `다시 처리`를 누릅니다. 본문이 없는 글은 성공으로 처리하지
않습니다. 다시 처리해도 실패하면 같은 카드의 `개발팀 문의용 정보 복사`를 사용합니다.

예상 상태: 완료한 단계는 유지되고, 아직 끝나지 않은 첫 단계만 다음 작업으로 표시됩니다.

## 3. 매일 운영 확인

`/operations`에서 `오늘 할 일`, `온보딩`, `보고서`, `문제·복구` 탭을 차례로 확인합니다.

| 상황 | 무슨 문제인지 | 고객 영향 | Admin에서 할 일 | 예상 상태 |
|---|---|---|---|---|
| 콘텐츠 또는 대표 이미지 생성 중단 | 예약 글의 일부가 준비되지 않음 | 예정된 공개가 늦어질 수 있음 | 상세에서 사유를 적고 `작업 다시 시도` | 새 작업이 접수되고 진행 상태가 표시됨 |
| 공개 후 Slack 확인 실패 | 글은 공개됐지만 운영 알림 기록이 없음 | 공개 성공과 알림 성공을 혼동할 수 있음 | 콘텐츠 화면 또는 상세에서 `Slack 다시 보내기` | 공개 상태는 유지되고 알림 상태만 갱신됨 |
| 무료 진단 측정 실패 | 환자 질문 측정을 완료하지 못함 | 진단 보고서를 만들 수 없음 | `/leads`에서 `다시 측정` | 새 측정 접수 상태가 표시됨 |
| 무료 진단 보고서 차단 | 측정 결과는 있으나 보고서를 열 수 없음 | 신청자에게 보고서를 보낼 수 없음 | `/leads`에서 `리포트 다시 만들기` | 기존 기록을 보존한 새 작업이 접수됨 |
| 공개 주소 확인 실패 | 병원 공개 주소가 정상 응답하지 않음 | 환자와 검색 서비스가 병원 정보를 열지 못할 수 있음 | 운영 센터의 안내에 따라 주소를 고친 뒤 `복구 결과 확인` | 정상 확인 뒤 문제 상태가 복구 확인으로 바뀜 |
| 공개 정보 갱신 실패 | 최신 공개 내용을 반영하지 못함 | 이전 정보가 잠시 보일 수 있음 | 운영 센터에서 다시 확인하고 `복구 결과 확인` | 최신 공개 정보 확인 시 복구 상태가 표시됨 |
| 일반 자동 작업 실패 | 연결된 고객 작업이 끝나지 않음 | 해당 결과가 고객 화면에 반영되지 않음 | 허용된 경우 `작업 다시 시도`, 없으면 문의 정보 복사 | 새 작업 또는 개발팀 전달 근거가 남음 |

Slack 상태는 고객 작업의 성공 여부와 별도입니다. `발송 완료`가 보여도 실제 고객 결과는 Admin의 작업 상태와
근거 화면에서 다시 확인합니다. 발송 결과가 불확실하면 중복 발송 여부를 Slack에서 먼저 확인합니다.

## 4. 콘텐츠 공개 후 확인

`/hospitals/{병원 ID}/content`에서 `지금 확인` 카드를 먼저 봅니다.

- 자동 공개가 차단된 글: 금지 표현과 근거 자료를 수정한 뒤 다시 공개합니다.
- Slack 알림 재시도: 글이 실제로 공개됐는지 확인한 다음 알림만 다시 보냅니다.
- 공개 내용 확인 대기: 공개 페이지를 열어 제목, 본문, 이미지가 맞으면 `문제 없음`을 누릅니다.
- 문제가 있는 공개 글: `문제 발견`을 누르고 비공개·재생성 절차를 진행합니다.

실패 문구에는 서버 응답 원문이 나타나지 않습니다. 같은 버튼을 다시 눌러도 해결되지 않으면
`개발팀 문의용 정보 복사`를 사용합니다.

## 5. 월간 보고서 검수와 전달

`/hospitals/{병원 ID}/reports`에서 다음 순서로 확인합니다.

1. 질문별 측정 근거와 비교 가능 여부
2. 원장 전달용 PDF 검증 결과
3. 이 보고서와 개별 연결된 Slack 알림 기록
4. 전달 가능 여부와 차단 사유
5. 전달·정정·철회 이력

측정이 빠졌거나 원장 전달용 PDF가 검증되지 않았으면 `운영 센터에서 확인`을 누릅니다. 화면이 이 보고서의
Slack 발송 성공을 증명하지 못하면 운영 센터에서 최신 알림을 확인합니다. 직접 해결할 버튼이 없으면
`개발팀 문의용 정보 복사`를 사용합니다.

전달 직전에는 서버가 최신 상태를 다시 확인합니다. 그 사이 상태가 바뀌어 차단되면 화면이 최신 근거를 다시
불러오고 문제 영역으로 초점을 옮깁니다. 전달 버튼을 반복해서 누르지 말고 새 차단 사유의 안내를 따릅니다.

예상 상태: 전달 성공이라는 표현 대신 `전달 기록을 남겼습니다`가 보이고, 정정·철회·재전달은 별도 이력으로 남습니다.

## 6. 화면과 접근성 확인

- 데스크톱, 태블릿, 모바일에서 가로 스크롤 없이 현재 작업과 조치 버튼이 보여야 합니다.
- 모든 주요 버튼과 입력칸은 손가락으로 누를 수 있는 높이를 가집니다.
- 모달은 `Tab`과 `Shift+Tab`으로 내부를 순환하고 `Escape`로 닫힙니다.
- 모달을 닫으면 열었던 버튼으로 초점이 돌아갑니다.
- 오류 후에는 다시 확인할 영역 또는 남아 있는 안전한 조치로 초점이 이동합니다.
