## 기존 문서의 지위

- `plans/`: 당시의 설계·실행 계획이다. Vercel/Supabase, Next 14, Imagen 3 등의 옛 구성을 현재 배포 지침으로 사용하지 않는다.
- `prd/`: 제품 요구와 의도에 관한 기록이다. 구현 완료를 보증하지 않으며, 현재 동작은 시스템 구조 문서와 코드를 함께 확인한다.
- `reviews/`, `handoff/`, 날짜가 붙은 `ops/monthly-contract-repair-*`: 특정 커밋·사건의 검수 기록이다. 원본 감사의 발견 사항은 보존하고 별도 후속 구현 기록에서 현재 상태를 연결한다.
- [DESIGN.md](../DESIGN.md): 시각 설계 기준이다. 운영 구조의 근거와 구분하며, 이 구조 조사에서 모든 화면의 시각 규칙을 재검수하지는 않았다.
- `sales/`, PDF·소개 자료: 대외 설명 자료다. 요금·모델·자동화 범위는 현재 코드 및 승인된 영업 정책과 대조한 뒤 재사용한다.

과거 문서의 본문을 현재 사실로 덮어쓰지 않고 기록으로 보존한다. 현재 안내 문서를 고칠 때에는 문서 버전, 갱신일, 확인한 코드 커밋, 검증 범위를 함께 갱신한다. 운영 환경변수는 코드 기본값과 다를 수 있으므로 실제 값을 확인하지 않은 항목은 반드시 기본값으로 표시한다.
