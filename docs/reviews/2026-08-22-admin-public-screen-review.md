## Wave 1 — Blocker / Critical

### A-1 (Blocker) 자기 도메인이 살아 있는데 화면은 "확인 대기"라고 말한다

`https://ai.no1top365.co.kr`는 HTTPS 200으로 응답하고 CNAME도 정상인데, Admin의
세 곳이 모두 아직 확인되지 않은 도메인이라고 표시한다.

1. 병원 목록의 도메인 열 → 주황색 **"공개 주소 확인 대기"**
2. 병원 상세 헤더 배지(모든 탭 공통) → **"저장됨 · DNS 미확인"**
3. `/profile` 도메인 트래커 단계 → **DNS 등록 대기 / DNS 검증 필요 / HTTPS 필요**

같은 화면의 온보딩 체크리스트와 대시보드는 같은 도메인을 **완료**로 표시한다.
한 병원의 같은 사실에 대해 화면이 서로 다른 답을 내놓고 있다.

**기대 동작** — 배지와 트래커를 감사 로그에 남은 과거 상태가 아니라 **실제 HTTPS
응답과 CNAME 조회 결과**로 갱신한다. 최소한 마지막으로 확인한 시각은 보여야 한다.
DomainSetup / 도메인 상태 / 인증서 / DNS 검증 코드 경로와 그 문구를 그리는 Admin
화면을 함께 본다. 이미 프로덕션에서 성공하고 있는 검증 결과를 제대로 소비하는 쪽을
우선하고, 도메인 판단 체계를 하나 더 만들지 않는다.

### A-2 (Blocker) 측정은 150/150 성공인데 노출 보완 작업은 전부 "성공 측정값 없음"

대시보드 로그: V0 첫 측정 완료, 성공 150/150, AI 답변 언급률 18.0%.
그런데 `/exposure-actions`의 12건과 대시보드 TOP3 카드가 모두 성공한
ChatGPT/Gemini 측정이 없다고 말하고, 진단 규칙은 **"성공 측정 없음"**이다.

**기대 동작** — 성공한 측정 기록이 존재하면 "성공 측정 없음" 진단 규칙이 발동해서는
안 된다. 측정 성공 여부를 판단하는 노출 보완 / 진단 규칙을 찾아, 대시보드가 18.0%를
계산하는 방식과 기준을 맞춘다.

### C-1 (Critical) 운영 기준의 "항목별 근거 연결" 24개가 전부 로드 실패, 재시도 수단 없음

오른쪽 패널의 24개 항목이 모두 **"근거 노트를 다시 불러와 확인이 필요합니다."**로
표시된다. 다시 불러올 수 있는 조작이 화면에 없다. 그런데 승인 체크리스트는 여전히
운영자에게 그 근거 연결이 맞는지 확인하라고 요구하고, 승인 버튼도 눌린다.

**기대 동작**

- (a) 항목별 또는 패널 단위의 재시도 버튼
- (b) 근거 연결 로드가 실패한 항목이 하나라도 있으면 사유 문구와 함께 승인을 잠근다

### P-A-1 (Critical) 공개 `/visit`의 "진료시간 보기"가 자기 자신을 가리키고 진료시간 표가 없다

`<a class="clinic-visit-action" href="…/visit">`가 지금 보고 있는 `/visit`을 다시
가리킨다. 그리고 `/visit` 문서에는 `<table>`이 하나도 없고 요일별 진료시간 문구도
없다.

**기대 동작** — `/visit`에 실제 요일별 진료시간 표를 그리거나(이미 JSON-LD와 llms에
쓰고 있는 병원 진료시간 / openingHours 데이터 사용), CTA가 그 표의 페이지 내 앵커를
가리키게 한다. 자기 자신으로 끝나는 막다른 링크는 남기지 않는다. Hospital에 이미
있는 진료시간 데이터를 쓰고, 없는 시간을 지어내지 않는다.

### F-1 (Critical) 상담 요청에서 병원을 만들면 이미 있는 병원이 중복 생성된다

`/leads`는 모든 상담 요청을 온보딩 대기로 보여주며 CTA가 "온보딩 시작 / 운영량 선택
후 병원 생성"이다. 장편한외과 상담 요청은 이미 운영 중인 병원을 가지고 있다.
`/hospitals/new`에는 중복 감지가 있지만 상담 요청 경로에는 없다.

**기대 동작** — 상담 요청에서 병원을 만들 때 `/hospitals/new`가 이미 쓰는 기준(이름·
전화·도메인 일치)으로 기존 병원을 감지하고, 중복 생성 대신 **상담 요청을 기존 병원에
연결**한다. 중복 생성은 막거나 경고한다. 상담 요청 온보딩 시작 흐름에 대한 변경은
최소로 한다.
