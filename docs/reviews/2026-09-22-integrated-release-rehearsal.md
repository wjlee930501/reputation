## 보고서 다운로드의 의도적인 계약 변경

원장용 월간/V0 PDF는 가변 GCS 객체의 signed URL로 redirect하지 않고 검증한 byte snapshot을
HTTP 200으로 제공한다. 내부 AE 판본의 기존 signed URL 동작은 유지한다. 과거 전달본의
열람은 현재 업무 readiness로 막지 않지만 실제 파일 일치는 확인한다. 무료/내부 리드도
같은 파일 검증을 사용한다. 토큰·병원 귀속·INTERNAL·파기·담당자·최신 판본 규칙은 유지한다.

스토리지 읽기는 async event loop 밖에서 수행한다. 파일 크기는 32MiB로 제한하고, 로컬은
REPORT_OUTPUT_DIR 하위만 읽는다. GCS는 지정된 보고서 버킷과 객체 generation을 확인하여
조건부로 읽은 뒤 SHA-256·크기를 대조한다. 이후 URL을 다시 서명하거나 파일을 재개방하지
않는다. 목록에는 새 원격 I/O를 추가하지 않았다. 기존 로컬 readiness의 파일 stat은 남는다.

## 검증의 구분

- Backend 전체 회귀는 빈 테스트 DB를 Alembic으로 구성하고 PostgreSQL·Redis·실제 PDF
  렌더링을 포함해 실행한다. 변경된 파일 검증에 맞춰 모의 artifact도 실제 digest/크기를
  갖게 했다. 잘못된 바이트·삭제·같은 크기의 교체는 별도의 거부 테스트로 확인한다.
- IndexNow는 무작위 실행 식별자와 실패와 무관한 cleanup을 사용해 동시 등록을 10회 반복한다.
- 스케줄 테스트는 예산이 남은 경우 정오, 소진된 경우 다음 날을 구분한다. 실제 loader의
  기한 직전 거부·기한 도달 허용도 확인한다.
- 이미지 한도는 재시도 가능 여부가 아니라 실제 획득한 claim만 센다. 앞선 유효 lease
  50개가 있는 경우에도 다음 적격 항목으로 진행하는 리허설을 포함한다.
- Linux/amd64 운영 Dockerfile, 실제 prefork Worker 2개, Redis 7개 큐, stock API/Beat,
  DB migration과 작업 서명을 `scripts/integrity_rehearsal/run.sh`로 검증한다.
- callback 처리 중 테스트 Worker를 종료한 뒤 재시작한다. DB에 남은 intent를 실제
  reconciler→Redis→Worker→HTTP callback으로 완료하고 SUCCEEDED 저장까지 확인한다.

## 외부 경계와 미검증 범위

HTTP AI 공급자는 실패를 반환하는 내부 fixture, 공개 갱신 callback도 내부 수신기다.
외부 호출·고객 발송·운영 DB 접근은 없다. 검증 fixture의 PUBLISHED 행은 미인증·비공개
테스트 입력이지 실제 공개 성공 증거가 아니다. 실제 큐 리허설은 성공한 이미지의 정책
검수·업로드·공개 화면 반영까지 증명하지 않는다. 이 성공 경로의 SQL 회귀와 큐 장애
회귀는 서로 다른 증거이며 합쳐서 완전 E2E라고 표기하지 않는다.
실제 GCS/IAM·상용 공급자·고객 수신함·운영 도메인·CDN·장기 Beat 주기는 별도 배포 전
검증 대상이다. 테스트의 PASS와 실제 운영 배포 완료를 구분한다.

최종 판정은 해당 PR의 고정 커밋 CI와 검증 artifact를 기준으로 한다. 이 문서 자체가
모든 작업의 성공 판정은 아니다. main 병합과 운영 배포는 별도 단계다.
