# 병원 이미지 전달 성능 개선 — 2026-09-16

기준선: `c4c3ac95f158620faceb71501ee17b835dd95c65`.
범위: 공개 Site의 이미지 전달·로딩·오류 복구. 원본 업로드와 Backend 공개 승인/이미지 인증은 변경하지 않는다.
이 문서는 배포 전 검토 기록이며 실제 운영 전환 결과는 PR과 release 기록에서 구분한다.

## 변경 내용

이미지 품질은 84에서 75로 조정하되 AVIF/WebP 협상은 유지한다. WebP-only 시도는
측정한 사진에서 전송량이 증가해 채택하지 않았다. 기존 q=84 URL도 계속 허용한다.
히어로·의료진·대표 글·목록·갤러리의 sizes를 실제 슬롯에 맞춰 별도 역할로 관리한다.
모바일 의료진은 104px 슬롯을 사용하고, 전체 폭 글 목록은 반쪽 폭 홈 대표 글과 분리한다.

홈의 첫 화면 히어로만 preload하고 아래쪽 대표 글과 갤러리는 lazy로 내려 경쟁을 줄인다.
글 상세와 목록의 첫 이미지에는 명시적인 eager/high 우선순위를 부여한다.
원장 사진은 JavaScript 마운트를 기다리지 않고 서버 HTML에서 발견된다.
커버와 초상의 fallback은 항상 이미지 아래에 있으며 초기 오류·1px 이미지·src 교체를
구분한다. 요청하지 않은 lazy 이미지를 실패로 처리하지 않는다.

인증된 캐시 무효화 이후에만 병원 한 곳의 승인된 히어로 750/1200px 변환을 준비한다.
공개 상태를 다시 확인하며 고정 loopback만 호출하고 요청자 Host·cookie·인증을 전달하지 않는다.
최대 2.5초·2개 크기·프로세스별 60초 중복 억제·128개 키 상한을 둔다.
준비 실패가 무효화 성공이나 공개 철회를 되돌리지는 않는다. 기존 Backend timeout은 10초다.
이 준비는 인스턴스 로컬 캐시이므로 모든 새 인스턴스의 cold start를 없앤다는 보장은 아니다.
