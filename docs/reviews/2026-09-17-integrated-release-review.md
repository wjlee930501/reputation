## 새벽 도메인 알림 운영 근거

Gcloud 재인증 후 기존 Worker 리비전의 로그를 조회했다(2026-09-17 KST).
03:45에 도메인 점검 두 건, 05:45에 한 건이 `tls_or_network_error`로 기록됐다.
03:45의 두 건은 04:30에, 05:45의 한 건은 06:30에 연속 정상 확인으로 자동 복구됐다.
이후 08:30까지 도메인 점검은 추가 실패 없이 수행됐으며 상태 저장 실패도 0건이었다.
행복드림의원 Admin GET은 08:30 점검의 `tenant_marker_ok`, `domain_last_check_ok=true`, 인증서 DONE, ACTIVE 공개 상태를 확인했다.
공개 주소와 권한 DNS·복수 공개 resolver·TLS 검증은 정상이다. DNS·인증서·Cloud Armor 규칙은 변경하지 않는다.

기존 로그는 TLS/연결/DNS 원인 예외를 단일 코드로 소실시키므로 하위 원인을 확정하지 않는다.
확인 가능한 사실은 일시적인 HTTPS 전송 실패와 이후 정상화다. 서버 요청 로그만으로 당시의 전체 이용자 영향을 단정하지 않는다.
운영센터 상세 API는 시스템 키에 403을 반환했으며 이를 우회하거나 사람 계정을 가장하지 않았다.
복구 판단은 worker의 durable transition 결과와 현재 병원 상태에 근거한다.

## 보완

실패 원인별 Slack 안내와 일시 실패의 1회 제한 재확인을 유지한다. TLS 검증·tenant identity·redirect 금지는 그대로다.
향후 ConnectError, DNS resolution, 인증서 검증 등의 원인을 구분할 수 있도록 병원 ID·host·예외 클래스 체인을 기록한다.
예외 메시지·헤더·인증 정보는 기록하지 않으며 회귀 테스트로 검증한다.
기존 정상 복구를 수동 ACK로 숨기거나 과거 오류를 성공으로 덮어쓰지 않는다.

통합 배포는 Backend API·Worker·Beat와 영속 RedBeat 일정을 함께 갱신해야 한다.
Site/Admin 소스와 DB 스키마·의존성 lock은 이번 변경 대상이 아니다.
배포 전 통합 테스트·원격 CI·최종 이미지 런타임 검증, 배포 후 DB head·현재 release 7개 큐·공개 병원 표면·오류 로그를 확인한다.
