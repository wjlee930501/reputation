# 원장용 월간 보고서와 진단 제안서 개편

기준 소스: main `9b2dac3910413cf0c29e7ceb6828dfdc83a7417b`.
범위: 보고서 데이터 뷰·템플릿·PDF 검증·호출부·Admin 검증 문구·회귀 테스트.
상태: 소스 구현과 격리 검증. 이 기록은 운영 배포나 실제 고객 전달을 뜻하지 않는다.

## 목적별 문서

월간은 ‘변화 → 제공한 정보와 활용 근거 → 다음 달 집중 질문’의 3쪽 본문과 전체 근거
부록이다. 진단은 ‘현재 확인된 기회 → 질문별 제안 → 첫 달 운영안과 상담’의 3쪽 본문과
측정 조건 부록이다. 기존 진단의 일반 회사 소개와 반복되는 검증 설명을 본문 중심에서
옮겼다. 내부용 진단은 모든 페이지에 AE 전용 표시가 있으며 고객 CTA·외부 링크가 없다.

동일한 Pretendard 기반 편집 규칙을 쓰되 월간은 네이비·청록의 비교 수치와 실제 근거,
진단은 구리색의 질문·제안·상담 행동을 중심으로 구성했다. A4 17mm 기준선, 본문 11pt,
주요 결과 28pt, 보조 문구 9pt를 기본으로 쓴다. 비교 막대는 0–100% 공통 눈금이며
비교 조건이 유효할 때만 이전 값과 %p 증감을 표시한다.

## 측정과 기여의 정합성

- 계산 엔진은 바꾸지 않았다. 월간 헤드라인은 지역·병원 선택 질문의 확정 반복을
  합산한 언급 비율(k/n)이다. 플랫폼별 세부 수치의 질문별 평균과 구분한다.
- 비교 가능한 동일 질문·플랫폼·모델·정책·반복 구성만 전후 비교에 사용한다.
  초기 참고값은 최초 측정이며 도입 전 성과로 이름을 바꾸지 않는다.
- 슬롯 이력이 없는 과거 자료는 0으로 만들지 않는다. MIXED는 알려진 일부 기록,
  LIMITED는 부분 확정으로 설명한다. 실패·보류·대기와 미언급을 구분한다.
- 완료한 발행, 병원명 언급, 실제 소유 콘텐츠 URL 인용을 구분한다. 콘텐츠 ID와
  병원 소유권으로 인용을 연결하며 제목 유사도를 기여 증거로 쓰지 않는다.
- 긍정·미언급 사례, 전체 질문표, 모든 발행·인용 기록을 부록에 남긴다. 긴 답변은
  본문에서 130자 요약으로 보여주고 보존한 발췌 전체는 부록에서 검증한다.

## 전달·호환성

월간 Worker가 명시적으로 새 MONTHLY 뷰를 사용한다. 새 아티팩트 검증 버전은
`doctor-pdf-v3`이며 본문 3쪽과 부록을 포함해 4–32쪽이다. 기존 v1/v2 저장 파일과
기존 초기 진단 경로는 계속 유효하다. Admin API·직렬화·인시던트 복구 SQL에 v3를
추가했으며 파일 hash, 한글 매핑, 필수 본문·부록·순서·링크 검증은 유지한다.

리드 PDF 템플릿은 `lead-v10`이다. 기존 allowlist에서 제안을 만들며 답변 원문·경쟁
병원명·내부 오류를 리드 payload에 추가하지 않는다. 기존 공개 토큰·재발송·INTERNAL
고객 발송 차단은 변경하지 않는다. 낮은 점수만으로 상위 요금제를 권하지 않으며
기존 가격·약정 편수를 유지한다. 발송을 늘리거나 지난 보고서를 자동 재생성하지 않는다.

## 검증과 미리보기

최종 Backend 전체 4,560개 통과(실패·오류·skip 0). 보고서·배포 스크립트 집중 회귀 195개 통과. 두 숫자는 중복되므로 합산하지 않는다. Ruff·문구 검사·DB 연결 예산·diff 검사를 통과했다.

최종 검수에서 소유 URL 인용 관측이 없는 상태를 0건으로 표시하던 부분도 수정했다. 이제 실제 0과 미확인을 데이터·PDF 부록에서 구분하며 회귀 테스트로 보호한다.

두 개의 긴 제목과 260자 답변 발췌 2개가 들어가는 사례도 실제 PDF로 검증했다.
Python 테스트는 운영 dotenv와 외부 연결을 차단하고 전용 loopback PostgreSQL 3개와
Redis를 쓴다. 기존 Alembic 경고와 순환 FK metadata 경고 2개는 남아 있다.

`scripts/report_design_samples.py`는 실제 렌더러에서 가상 PDF 8종을 만든다. 모든 쪽에
‘검증용 가상 사례’를 표시한다. CI는 PDF와 manifest만 보관하며 폰트·HTML·운영자료는
업로드하지 않는다. `--png`는 로컬 시각 검수를 위한 HTML·PNG·텍스트를 추가 생성한다.
각 지면의 근거 텍스트·좌표와 부록 누락을 검증하고, 실제 PNG를 확인한다.

운영 배포, 운영 DB 조회·변경, 유료 모델 호출, Slack·이메일·SMS 발송은 하지 않았다.
기존 생성물은 그대로이며 실제 서비스에는 별도 배포 이후 새로 생성되는 보고서부터
적용된다. 닫힌 보고서를 갱신하려면 기존 명시적 재생성 절차를 사용해야 한다.
