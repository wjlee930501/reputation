## 0. 한 문단 판정

**측정과 공개 표면은 업계 기준 이상으로 잘 만들어졌고, 콘텐츠 생성·발행·재시도는 진짜 자율적이다. 그러나 가치가 만들어지는 인과 고리 세 개가 끊겨 있다.** ① 측정된 격차가 "무엇을 쓸지"를 결정하지 않는다(유형은 정적 배분표, 타깃은 한 줄 힌트). ② "우리 글이 AI에 인용됐는가"를 글 단위로 귀속하는 코드가 없고, 플랫폼 경로 허브는 인용돼도 0으로 집계된다. ③ 원장이 받는 헤드라인은 셀당 5회 측정 중 1회만 쓴 20~30개 이진 표본이라 월간 증감을 신뢰할 수 없다. 여기에 사람 개입은 "최소"가 아니라 온보딩 12~18회 제출·35개 이상 입력, 운영 중 병원당 월 10~20회 터치이며, 그 절반 이상은 시스템 자신의 기계 신호다. 코드 주석의 자체 실측(`indexnow.py:3-10`)이 핵심을 말한다: **허브가 인용되면 93% 언급, 아니면 4%**. 즉 언급률은 인용률의 함수인데, 현재 제품은 "인용 가능한 글을 꾸준히 낸다"까지만 하고 "인용되게 만든다"와 "인용됐는지 확인해 다음 달을 바꾼다"가 없다.

## 1. 가치 ①: AI 답변 언급 — 인과 루프는 닫혀 있는가

### 1.1 잘 된 것 (강한 고리)
- **질의 설계**: `sov_engine.py:269-294` LOCAL 10종("{region} {clinic} 추천해줘", "{sub_region} {keyword} 진료 가능한 병원", "{region} {specialty} 진료비 어느 정도야?") + INFO 5종. 키워드를 질환/증상/부위/시술로 분류해 문법에 맞는 템플릿에만 결합(`keyword_analysis.py:85-156`, `sov_engine.py:427-454`). 병원명은 질의에 넣지 않음. 지역 없는 INFO 질문은 언급률 분모에서 제외. 가치 제안의 질문 형태와 정확히 일치한다.
- **측정 프로토콜**: ChatGPT는 Responses API + `web_search`(강제하지 않고 모델이 선택, `tool_choice=auto`), Gemini는 GoogleSearch grounding, 양쪽 동일 시스템 지시문을 같은 역할로 전달(`sov_engine.py:706-850`). 인용 URL(`source_urls`), 검색 호출 수, 응답 모델을 기록. 프로토콜 지문·응답 모델 변경 감지·AMBIGUOUS 3값 판정·허위 0 금지. 경쟁사 언급도 같은 답변에서 판정.
- **공개 표면**: Article(citation, datePublished, isPartOf)·FAQPage·MedicalProcedure/HowTo·MedicalCondition·MedicalClinic+LocalBusiness+Physician JSON-LD, canonical, 병원별 llms.txt, AI 크롤러 12종 명시 허용, 발행 즉시 ISR revalidate + IndexNow 제출. 승인 데이터만 노출.
- **안전 게이트**: 금지 표현·가격 주장·화이트리스트 references 필수·병원명/원장명/지역 하드 포함.

### 2.3 알림·주의 큐의 신호 대 잡음

### 3.1 원장용 1페이지에 실제로 있는 것 (`templates/doctor_report.html`, 뷰 `report_engine.py:543-693`)
① "이번 달 환자 질문 100번 중 AI가 {병원}을 답변에 넣은 횟수는 N번입니다" ② "챗GPT, 제미나이에서 계획한 답변 30개 중 30개 확인" ③ "지난달 39번 → 이번 달 47번 (8개 늘었습니다)" 또는 "이번 달이 기준선입니다" ④ 타일 1개: 발행 편수 ⑤ 새로 언급된 질문 최대 5개 ⑥ 나온 사례 1개 + 안 나온 사례 1개 ⑦ 각주("5개 안팎 오르내림은 정상").

### 3.2 없는 것
- **경쟁 병원 비교 없음** — 뷰가 계산하지만 템플릿이 렌더하지 않고 테스트가 부재를 의도로 고정(`test_doctor_report_view.py:161-171, 273`).

- 1페이지 강제 검증(`report_artifact_validation.py:49-53`)이라 위 항목을 추가하면 막힌다.

### 3.3 헤드라인 숫자의 통계적 실체
- 월간 측정도 셀당 5회 반복(`SOV_REPEAT_WEEKLY=5`, `tasks.py:706, 3417`)을 **결제**하지만, `selected_attempt`는 가장 이른 성공 1건(`monthly_sov_types.py:58-65`)이고 `_macro_rate`(`monthly_sov.py:14-30`)와 전월 비교가 그것만 쓴다. 반복이 동시(gather)라 `measured_at`이 동률 → tie-break가 UUID → **성공 5개 중 사실상 무작위 1개**. 테스트가 "반복은 점수를 바꾸지 않는다"를 의도로 고정(`test_monthly_sov_comparability.py:65-82`).
- 플랫폼당 n=15 → 셀 하나 뒤집히면 6.7%p, 두 플랫폼 매크로면 3.3%p. p≈0.3에서 헤드라인 SD≈8.4%p, 전월 대비 차이 SD≈12%p, 95% 구간 ≈ ±23. **3점 변화는 셀 하나, 10점 상승도 1SD 이내.**
- 원장용은 `delta > 0`이면 무조건 "(N개 늘었습니다)"(`report_engine.py:585`). 각주의 `NORMAL_FLUCTUATION = 5`(`:488`)는 통계 근거 없는 상수로 실제 노이즈의 1/4~1/5. "100번 중 N번" 표현은 100회 표본을 암시해 정밀도를 과장 [L].
- **헤드라인 분모와 델타 분모 불일치**: `sov_pct = monthly_sov.sov_pct`(전 셀) vs `prev_sov = comparison.prior_sov_pct`(매칭 셀만)(`tasks.py:5025-5027`). 지난달 셀 하나가 실패하면 30셀 vs 29셀 비교.
- 잘 된 것: AMBIGUOUS 분모 제외, 허위 0 금지, 응답 모델 변경 시 비교 차단(`monthly_sov.py:141-254`, NON_COMPARABLE 사유 7종). "틀린 델타"가 나갈 확률은 낮다. 다만 나가는 델타도 노이즈와 구분되지 않는다.

### 3.4 1일 00:15에 나올 확률
`customer_ready`까지 게이트 7~8개: 전환 병원은 월간 SoV run SUCCEEDED 아니면 **배치에서 조용히 제외**(`tasks.py:5280-5284`); manifest 셀 하나라도 실패면 DEGRADED → `coverage_incomplete`(`reports.py:228-238`), 마감 후 재측정 경로 없음, 시도 기록 있는 셀은 OWNER도 제외 불가(`exclude_cell:224-225`); 원장 PDF 1페이지·폰트·문구 검증; **후행 검수 샘플 미완료 → 차단**(사람 의존); **Essence 승인 버전이 리포트 생성 후 바뀌면 "다시 생성"**(`reports.py:270-293`) — 9월 초에 AE가 자료 하나 올리면 8월 리포트가 전달 불가로 바뀐다. 첫 몇 달은 병원별로 절반 안팎이 1일 자동 통과 못 할 것으로 본다 [L]. 8월(전환 첫 달)은 tracking set 등록 실패 병원은 리포트가 아예 생성되지 않음.

## 4. 종합 — 아키텍처 에너지가 어디에 쓰였는가

코드베이스의 무게중심은 **운영 통제 기계**(1분 폴러 4종, canary 6종, 인시던트 타입 30여 종, 마일스톤 투영, outbox, 3중 복구 루프, 지문·프로토콜 동결, sha 바인딩 전달)에 있다. 이것은 "시스템이 조용히 틀리지 않는다"는 데는 탁월하지만, 가치 제안의 세 축에 대해서는 역설적으로 작용한다.

- **가치 ①에는 부족**: 격차→주제 결정, 인용 귀속, 권위 확보처럼 언급률을 실제로 움직이는 로직에는 투자가 얇다. 측정 엔진이 만든 풍부한 데이터(`source_urls`, `competitor_mentions`, `mention_rank`, 5회 반복)를 콘텐츠 계획과 리포트가 거의 쓰지 않는다.
- **가치 ②에는 역효과**: 통제 기계가 만든 신호의 절반 이상이 AE에게 "확인 완료"·"기다리세요"·"다시 시도"를 요구하고, 리포트 게이트가 인접 운영 위생(후행 샘플, Essence 버전)까지 하드로 묶어 사람을 끌어들인다.
- **가치 ③에는 반쪽**: 비교 게이트·검증은 원장에게 틀린 숫자가 가지 않게 하지만, 그 숫자 자체의 표본이 얇고 이야기(무엇을 했고 다음에 뭘 할지)가 빠져 휴먼터치의 재료가 되지 못한다.

## 5. 최고 레버리지 변경 (제품 수준, 우선순위순)

### 가치 ① 언급률
1. **인용 귀속을 1급 데이터로.** `source_urls`를 정규화해 `ContentItem`(플랫폼 경로·서브도메인·커스텀 도메인 모두)과 매칭하는 `ContentCitation`을 만들고, 헤드라인을 "언급률"과 **"우리 글 인용률"**로 이원화. 최소 수정은 `_owned_source_roots`에 플랫폼 경로 추가.
2. **격차가 슬롯을 만들게.** `PLAN_DISTRIBUTION`을 "월 편수 상한"으로 낮추고, 슬롯의 유형·주제·제목 앵글을 `MISSING_MENTION` 타깃의 질의 문장에서 파생(FAQ의 `faq_question`을 그 질문 자체로 고정, LOCAL 프롬프트에 측정 지역·키워드만 주입). 생성 검증에 "target_query의 임상 키워드가 제목·첫 H2·faq_question에 존재"를 하드 게이트로.
3. **인용률을 올리는 레버를 제품 안으로.** 자기 도메인 연결을 온보딩 기본값으로, 병원 홈페이지·플레이스·허브 간 NAP 일관성 점검과 상호 링크를 `ExposureAction`의 실행 가능한 항목으로, 측정에서 인용된 경쟁 URL 유형(디렉터리·블로그·플레이스) 분포를 수집해 "AI가 이 질문에 실제로 읽는 소스"에 맞춘 배포 전략을 월간 계획에 반영.
4. **판정기 하한 손질.** 3000자 절단 제거 또는 병원명 주변 윈도우 추출, prefilter 키를 별칭 집합(AE 등록)으로 확장, `mention_rank`·부정 문맥을 "추천 후보로 언급됨" 보조 지표로 분리.
5. **모든 활성 병원에 tracking set(N=15) 자동 등록**, 코호트 진입을 병원명 하드코딩에서 `Hospital` 플래그로.

11. **표본을 통계로 승격**: 이미 결제한 5회 반복을 셀당 빈도(k/5)로 채택해 실효 표본 30→150, `NORMAL_FLUCTUATION` 상수 대신 Wilson 구간으로 "의미 있는 변화/정상 범위"를 코드가 판정. 헤드라인과 델타가 같은 매칭 셀 집합을 쓰게(`tasks.py:5025-5027`).
12. **원장 1장을 3막 구조로**: "우리가 한 일(발행 글 제목 3~5개 + AI가 인용한 자사 URL 건수) → 변한 것(헤드라인 + 새로 나온 질문 **+ 빠진 질문**) → 다음 달(이미 계산되는 `next_actions` 상위 2개 + 원장께 부탁 1개)". 1페이지 검증은 유지하되 2쪽 부록(질문 15개 전체표: 지난달/이번달/경쟁사 최다 언급)을 별도 규칙으로 허용.
13. **베이스라인 연속성**: V0를 tracking set과 같은 질문·프로토콜로 manifest(`period 0`)로 저장하고 "시작 시점 대비" 축 추가.
14. **게이트를 "리포트 진실성"과 "인접 운영 위생"으로 분리**: 사후검수·Essence 버전·자료 미처리는 경고로, 마감 후 실패 셀은 OWNER가 사유를 남기고 제외 가능. 목표는 "1일 00:15에 코호트 전부 전달 가능".
15. **AE 미팅 키트 자동 생성**: 리포트 JSON에서 3문단 토킹 스크립트·질문별 표 CSV/슬라이드·숫자 포함 Slack(`notify_monthly_report_ready` 재연결 또는 마일스톤에 헤드라인·델타 포함)을 Admin "미팅 자료 내려받기"로. 원장이 손댈 한 가지(다음 달 주제 3개 중 선택)를 리포트에 넣어 대화를 승인 행위로 끝내게.

## 6. 이 문서와 선행 리뷰의 관계
선행 문서(`comprehensive-architecture-review.md`)의 §2 최우선 조치(비공개 리밸리데이션 복구, 마이그레이션 드리프트, V0 재시도 비용, prompt cache, cost_guard 우회, compose/CI 배선)는 **위생과 비용**의 문제다. 이 문서의 15개 항목은 **가치 창출**의 문제다. 순서를 정한다면, 선행 문서 §2의 1~3번(리스크)을 먼저 막고, 그다음은 이 문서의 1·2·11·6·8번(인용 귀속, 격차 기반 슬롯, 5회 반복 승격, 자동 활성화, 샘플 게이트 분리)이 투입 대비 가치가 가장 크다.
